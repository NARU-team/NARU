# NARU | 나루
### 차에서 머무는 모든 순간을 나만의 쉼으로.

<img width="8000" height="5115" alt="나루_차량화면_목업" src="https://github.com/user-attachments/assets/3addb8e1-b100-4ed9-bc9d-a29775ecc9fd" />

**나루(NARU)는 장소와 차량 상태를 이해하고, 차박부터 짧은 낮잠까지 온도·조명·소리·기상 환경을 하나의 흐름으로 연결하는 차량용 AI 휴식 에이전트입니다.**

**Pleos Connect 기반의 차량 특화 휴식 경험**을 제안합니다.

---

## 📦 앱 다운로드 · 실행 방법

### 다운로드

| 버전 | 파일 | 비고 |
|---|---|---|
| v0.1.0 | [NARU-v0.1.0.apk](https://github.com/NARU-team/NARU/releases/download/v0.1.0/NARU-v0.1.0.apk) | 시연용 debug 빌드 (차박 모드) |

전체 릴리스 목록은 [Releases](https://github.com/NARU-team/NARU/releases)에서 볼 수 있습니다.

### 실행 환경

- Android Studio (최신 버전)
- **Pleos Connect Emulator v2.1.0** (Android Automotive, API 34)
  - Android Studio → SDK Manager → SDK Update Sites에 아래 주소 추가 후 시스템 이미지 설치
    - Mac: `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-arm64-sys-img.xml`
    - Windows/Linux: `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-sys-img.xml`
  - Device Manager → Form Factor `Automotive` → `Pleos Connect v2.1.0`으로 AVD 생성
  - AVD 설정에서 **Default boot = Cold boot** (Quick boot면 차량 기능이 동작하지 않음), RAM 4GB
- 인터넷 연결 (날씨·물때·야영장 정보와 AI 안내는 중계 서버를 거쳐 받아 옵니다)

### 설치·실행

1. 에뮬레이터를 Cold boot로 켜고 부팅이 끝날 때까지 기다립니다.
2. APK를 설치합니다. 에뮬레이터 화면에 APK 파일을 끌어다 놓거나, 터미널에서 아래 명령을 실행합니다.
   ```bash
   adb install -r NARU-v0.1.0.apk
   ```
3. 에뮬레이터 하단 앱 목록에서 **NARU**를 실행합니다. 또는:
   ```bash
   adb shell am start -n ai.naru.app/.MainActivity
   ```
4. 처음 실행하면 위치 권한을 허용합니다. (거부하면 시연 지역을 직접 고를 수 있습니다)
5. 기어가 **P(주차)** 상태일 때 홈에서 **차박 모드 → 시작**을 누릅니다.

### 공조·조명 제어 확인 (Virtual Console)

에뮬레이터의 공조·조명 제어는 **Virtual Console이 열려 있는 동안에만** 반영됩니다.

```bash
adb forward tcp:8088 tcp:8088
```

브라우저에서 `http://127.0.0.1:8088/`을 열어 둔 채로 앱을 사용하세요. 기어(P/R/N/D), 배터리 잔량, 공조·조명 상태도 이 화면에서 바꾸거나 확인할 수 있습니다.

> 💡 에뮬레이터가 무거워 멈추거나 재시작되면 다른 앱(브라우저 탭, 디자인 툴 등)을 줄이고 Cold boot로 다시 켜 주세요.

### 소스에서 직접 빌드

```bash
git clone https://github.com/NARU-team/NARU.git
cd NARU
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

- JDK 17, Android SDK 35가 필요합니다.
- 결과물: `app/build/outputs/apk/debug/app-debug.apk`

### 왜 나루인가?

자동차는 이동을 위한 공간이지만, 운전자에게는 잠시 쉬거나 하룻밤 머무는 공간이기도 합니다.

그러나 차에서 휴식을 취하려면 여러 기능을 따로 조작해야 합니다.

- 차박 장소의 이용 가능 여부와 주변 환경 확인
- 날씨, 기온, 물때, 일출 시각 검색
- 차량 공조 및 실내 조명 설정
- 휴식에 적합한 소리 선택
- 기상 알람 설정
- 배터리 잔량 확인
- 휴식 종료 후 기존 차량 설정 복구

나루는 이러한 과정을 **'지금 쉬고 싶다'는 하나의 목적**으로 연결합니다.

사용자는 원하는 휴식 방식과 시간을 선택하고, 나루가 제안한 환경을 확인하면 됩니다.

**차량 기능을 각각 조작하는 경험에서, 휴식이라는 목적을 중심으로 차량을 사용하는 경험으로 전환하는 것이 나루의 목표입니다.**

## 2. 핵심 서비스

나루는 사용자의 휴식 목적에 따라 두 가지 모드를 제공합니다.

| 구분 | 차박 모드 | 쉼표 모드 |
|---|---|---|
| 이용 상황 | 주차 중 하룻밤 차박 | 주차 중 짧은 낮잠과 휴식 |
| 주요 목적 | 장소와 환경을 고려한 숙박형 휴식 | 빠른 휴식 준비와 편안한 기상 |
| 핵심 정보 | 위치, 날씨, 물때, 일출, 배터리 | 휴식 시간, 실내 온도, 배터리 |
| 환경 설정 | 공조, 테마 소리, 조명 | 공조, 화면 밝기, 자연음, 조명 |
| 기상 방식 | 일출 시각 기반 빛 기상 | 설정 시간 기반 알람 |
| 종료 처리 | 아침 브리핑 및 차량 설정 복구 | 휴식 기록 및 차량 설정 복구 |

### 2.1 차박 모드 | 오늘 여기서 자기

차박 모드는 차량을 단순한 이동 수단이 아닌 하룻밤 머무는 공간으로 활용하는 기능입니다.

**① 도착 안내**

차량의 현재 위치를 기준으로 주변 야영장과 날씨, 물때, 장소 이용 정보를 확인합니다.

수집한 정보를 바탕으로 다음과 같이 안내합니다.

- 정보 확인
- 현장 확인 필요
- 주의·이동 권장

차박 허용 여부처럼 데이터만으로 확정할 수 없는 사항은 임의로 판단하지 않고 현장 안내판 확인을 요청합니다.

**② 취침 준비**

밤 최저기온과 이전 휴식 기록을 활용해 적절한 실내 온도를 추천합니다.

충분한 실측 데이터가 확보되면 예상 배터리 잔량을 범위로 안내하고, 일출 시각을 기준으로 기상 시간을 제안합니다.

**③ 취침 중**

해변, 숲, 호수 등 장소에 어울리는 테마를 선택해 화면, 소리, 조명을 구성합니다.

사용자는 테마 지속 시간을 설정하고, 소리와 조명을 각각 제어할 수 있습니다.

테마가 종료되더라도 공조와 기상 알람은 유지되도록 설계합니다.

배터리 잔량이 설정한 하한에 가까워지면 경고를 제공합니다.

**④ 기상 및 종료**

설정한 기상 시각에 화면과 조명을 점진적으로 밝히는 기상 경험을 제공합니다.

이후 밤사이 실내 온도와 배터리 변화를 요약한 아침 브리핑을 보여 주고, 휴식 중 변경한 차량 설정을 원래 상태로 복구합니다.

### 2.2 쉼표 모드 | 잠깐 쉬어가기

쉼표 모드는 외근, 장거리 운전, 일정 사이 대기 등 짧은 휴식이 필요한 상황을 위한 기능입니다.

**① 휴식 시간 설정**

15분, 30분, 45분 중 원하는 시간을 선택하거나 직접 입력합니다.

휴식을 시작하기 전에 종료 예정 시각을 보여 주어 다음 일정과 겹치지 않는지 확인할 수 있습니다.

**② 휴식 환경 준비**

현재 실내 온도와 차량 상태를 확인하고, 사용자가 선택한 환경을 적용합니다.

차량 제어가 지원되는 환경에서는 공조와 조명 설정을 백업한 뒤 변경하도록 설계합니다.

**③ 휴식 진행**

휴식 중에는 다음 정보를 제공합니다.

- 남은 휴식 시간
- 종료 예정 시각
- 휴식 진행 상태
- 실내 온도와 배터리 상태
- 휴식 연장 및 즉시 종료 기능

타이머는 단순 화면 카운트가 아닌 시스템 경과 시간을 기준으로 관리합니다.

**④ 기상 알람 및 연장**

설정 시간이 종료되면 부드러운 알람과 기상 화면을 제공합니다.

사용자는 다음 중 하나를 선택할 수 있습니다.

- 5분 더 쉬기
- 10분 더 쉬기
- 휴식 종료

응답이 없는 경우에는 정해진 확인 시간이 지난 뒤 자동 종료하도록 설계했습니다.

**⑤ 종료 및 복구**

휴식이 끝나면 실제 휴식 시간과 종료 시각을 표시합니다.

변경된 설정의 복구 결과를 확인하고, 휴식 기록을 로컬 데이터베이스에 저장합니다.

차량에서 지원하지 않는 기능이나 측정할 수 없는 정보는 임의의 성공값으로 표시하지 않습니다.

## 3. 나루만의 차별점

### 3.1 기능 중심이 아닌 목적 중심의 차량 경험

기존 차량 기능은 공조, 조명, 오디오, 알람처럼 개별적으로 제공됩니다.

나루는 사용자의 목적에 맞춰 이 기능들을 하나의 흐름으로 연결합니다.

예를 들어 사용자가 "30분만 쉬고 싶다"고 요청하면, 나루는 휴식 종료 시각과 실내 환경을 함께 제안하는 방식입니다.

### 3.2 차량 내부와 외부 환경의 연결

차박 모드는 차량 내부 정보뿐 아니라 날씨, 장소, 물때, 일출 시각까지 고려합니다.

차량이 위치한 장소와 시간에 따라 필요한 정보와 휴식 환경이 달라진다는 점에 주목했습니다.

### 3.3 휴식 종료 후 원상 복구

휴식 환경을 조성하는 것만큼 중요한 것은 종료 후 기존 상태로 돌아가는 것입니다.

나루는 설정 변경 전 값을 백업하고, 정상 종료나 중단 상황에서 복구를 시도하는 구조를 지향합니다.

### 3.4 사용자 승인 기반의 AI

AI는 휴식 환경과 안내 문장을 제안하지만, 차량 제어를 독자적으로 결정하지 않습니다.

실제 제어는 지원 여부와 안전 조건을 확인하는 규칙 기반 로직이 담당하며, 설정 변경은 사용자 승인 이후 실행하도록 설계합니다.

## 4. 현대자동차그룹 Pleos Connect 활용

나루는 현대자동차그룹의 차세대 인포테인먼트 플랫폼인 **Pleos Connect**를 기반으로 차량에 특화된 휴식 서비스를 구현하는 것을 목표로 합니다.

Pleos Connect 환경의 대화면 UI와 차량 상태 정보, 차량 제어 기능을 활용해 스마트폰 앱과 차별화되는 차량 중심 경험을 제공합니다.

### 4.1 Pleos Connect SDK 및 API

| SDK / API | 활용 |
|---|---|
| Vehicle (HVAC) | 실내 온도 조회, 공조 설정 확인 및 변경, 종료 후 복구 |
| Vehicle (Light) | 앰비언트 조명 색상·밝기 조회 및 변경 |
| Vehicle (EvBattery) | 배터리 잔량 조회, 변화 기록, 하한 경고 |
| FusedLocation | 차량 위치 기반 야영장·날씨·물때 정보 검색 |
| TextToSpeech | 도착 안내, 취침 준비, 기상 브리핑의 한국어 음성 출력 |
| SpeechToText | 음성 기반 온도·기상 시각·테마 변경 요청 |
| AAOS GEAR_SELECTION | 주차 상태 확인 및 주행 전환 시 휴식 종료 |
| Android Audio API | 자연음 및 기상 알람 재생 |
| Android Room | 휴식 기록과 로컬 상태 저장 |


### 4.2 Gleo AI 연동 방향

현대자동차그룹의 차량용 AI 생태계인 **Gleo AI**를 활용해 자연어 기반 휴식 설정 경험으로 확장할 계획입니다.

예상 사용자 요청은 다음과 같습니다.

| 사용자 요청 | 나루의 처리 방향 |
|---|---|
| "나 20분만 쉴래" | 휴식 시간과 종료 예정 시각을 설정하고 환경을 제안 |
| "조금 더 따뜻하게" | 현재 공조 설정과 지원 범위를 확인한 뒤 변경 제안 |
| "해 뜰 때 깨워 줘" | 위치 기반 일출 시각을 확인하고 기상 시간 제안 |
| "오늘 밤 추울까?" | 밤 최저기온과 실내 온도를 함께 안내 |

AI는 사용자 의도를 해석하고 추천·설명을 제공하는 역할을 맡습니다.

차량 제어와 안전 관련 판단은 별도의 규칙 기반 로직에서 처리합니다.

### 4.3 차량 안전 및 제어 원칙

차량 제어는 다음 순서로 수행하도록 설계합니다.

1. 주차 상태 확인
2. 차량 기능 지원 여부 확인
3. 기존 설정 백업
4. 사용자 승인
5. 설정 적용
6. 변경 결과 확인
7. 종료 시 기존 설정 복구

기어가 P 상태가 아니면 휴식 시작을 제한하고, 휴식 중 주행 상태로 전환되면 세션을 종료하는 것을 원칙으로 합니다.

차량 제어에 실패하면 무제한으로 재시도하지 않고, 사용자에게 실패 상태와 직접 조작 필요 여부를 안내합니다.

실제 차량 연동이 지원되지 않는 환경에서는 화면, 알람, 로컬 기록 등 이용 가능한 기능을 중심으로 동작하도록 구성합니다.

## 5. 시스템 아키텍처

나루는 차량 내 Android 애플리케이션과 차량 SDK, 외부 정보 API 및 AI 중계 서버를 분리하는 구조를 지향합니다.

```text
                     사용자
                       |
                       v
              NARU 차량용 앱
           Kotlin / Jetpack Compose
                       |
          +------------+------------+
          |            |            |
          v            v            v
      차박 모드      쉼표 모드     AI 인터페이스
          |            |            |
          +------------+------------+
                       |
                서비스 로직
          상태 관리 / 규칙 기반 제어
                       |
        +--------------+---------------+
        |              |               |
        v              v               v
   Pleos Connect    Android 로컬     외부 API / AI
   SDK 연동 계층     데이터 계층      중계 서버
        |              |               |
   HVAC / Light       Room          날씨 / 물때
   EvBattery          타이머        장소 정보
   FusedLocation      휴식 기록     생성형 AI
   TTS / STT
```

외부 정보와 AI 기능은 중계 서버를 통해 접근하도록 설계해 API 키 관리와 서비스 로직을 분리합니다.

차량 제어는 AI 응답에 직접 연결하지 않고, 사용자 승인과 차량 상태 검증을 거쳐 실행하도록 구성합니다.

## 7. 사용자 시나리오

### 시나리오 A. 차박 여행자의 하룻밤

차박을 즐기는 사용자가 동해 바닷가 자동차야영장에 도착합니다.

나루는 현재 위치를 기준으로 밤 날씨와 물때를 확인하고, 차박 장소의 이용 조건을 안내합니다.

사용자는 현장 안내판에서 이용 가능 여부를 확인한 뒤 차박을 준비합니다.

나루는 밤 기온과 이전 기록을 참고해 적절한 실내 온도를 제안하고, 일출 시각을 기준으로 기상 시간을 설정하도록 돕습니다.

사용자는 해변 테마를 선택하고 파도 소리와 조명을 활용해 휴식을 시작합니다.

아침에는 일출에 맞춰 화면과 조명이 서서히 밝아지고, 밤사이 차량 상태를 요약한 브리핑을 확인합니다.

휴식을 종료하면 변경했던 차량 설정을 원래 상태로 복구합니다.

### 시나리오 B. 외근 중 30분 휴식

오전부터 외근을 이어 온 직장인이 다음 일정까지 40분의 여유가 생겼습니다.

주차장에 차를 세운 뒤 나루의 쉼표 모드를 실행하고 30분을 선택합니다.

나루는 종료 예정 시각을 먼저 보여 주고, 사용자가 확인한 환경으로 휴식을 시작합니다.

휴식 시간이 끝나면 알람이 울립니다.

사용자는 5분을 추가로 쉬기로 결정하고, 연장된 시간이 끝난 뒤 휴식을 종료합니다.

나루는 휴식 기록과 설정 복구 결과를 보여 줍니다.

사용자는 별도로 여러 차량 기능을 다시 조작하지 않고 다음 일정으로 이동할 수 있습니다.

## 8. 기대효과

### 8.1 사용자 가치

| 기대효과 | 제공 가치 | 성과 측정 지표 |
|---|---|---|
| 휴식 준비 과정 간소화 | 여러 앱과 차량 설정을 하나의 흐름으로 통합 | 휴식 시작까지 걸린 시간, 터치 수 |
| 배터리 불안 완화 | 잔량 정보와 하한 경고, 예상 범위 제공 | 예측 범위 적중률, 공조 수동 변경 횟수 |
| 휴식 경험 개선 | 환경 맞춤 설정과 기상 경험 제공 | 휴식 만족도, 긍정 피드백 비율 |
| 개인화 | 이전 기록과 피드백을 다음 추천에 반영 | 추천 설정 채택률 |
| 재방문 유도 | 짧은 휴식과 차박을 함께 제공 | 재사용률, 월간 활성 사용자 수 |

위 지표는 향후 실제 사용자 테스트를 통해 측정할 계획입니다.

### 8.2 타깃 사용자

**1차 타깃: 차박 및 차량 기반 여행 이용자**

차량을 숙박 공간으로 활용하며, 장소 정보와 차량 환경을 함께 관리하고 싶은 사용자입니다.

**2차 타깃: 짧은 휴식이 필요한 운전자**

장거리 운전자, 외근이 잦은 직장인, 일정 사이 차량에서 대기하는 사용자입니다.

차박은 주말과 여행 중심의 이용 경험이고, 쉼표 모드는 평일에도 반복적으로 사용할 수 있다는 점에서 두 기능은 상호 보완적입니다.

### 8.3 예상 사용자 규모

다음 수치는 실제 서비스 운영 성과가 아닌, 기획 단계에서 설정한 가정 기반 추정치입니다.

예상 MAU 계산식:

```text
예상 MAU = Pleos Connect 탑재 차량 수 × 앱 설치율 × 월간 활성률
```

| 항목 | 출시 첫해 가정 | 2030년 가정 |
|---|---:|---:|
| 국내 대상 차량 | 500,000대 | 약 3,460,000대 |
| 앱 설치율 | 8% | 8% |
| 월간 활성률 | 30% | 30% |
| 예상 MAU | 약 12,000명 | 약 83,000명 |

이는 기획서에서 설정한 시나리오 기반 목표치이며, 실제 Pleos Connect 보급 및 사용자 확보 결과에 따라 달라질 수 있습니다.

### 8.4 리텐션 목표

| 모드 | 목표 지표 | 목표 |
|---|---|---|
| 차박 모드 | 60일 재사용률 | 35% |
| 쉼표 모드 | 4주 리텐션 | 25% |

차박은 여행·계절성 이용을 고려해 60일 기준으로, 쉼표 모드는 일상적인 반복 이용을 고려해 4주 기준으로 평가할 계획입니다.

## 9. 발전 가능성 및 확장 계획

### 9.1 개인화된 차량 휴식 환경

휴식 기록과 사용자 피드백이 축적되면 선호 온도, 조명, 기상 방식 등을 반영한 개인화 추천으로 발전시킬 수 있습니다.

### 9.2 Pleos App Market 기반 서비스 확장

향후 Pleos App Market의 콘텐츠 유통 및 결제 기능을 활용해 지역·계절별 테마와 프리미엄 사운드 콘텐츠를 제공하는 방안을 검토합니다.

### 9.3 캠핑·여행 서비스 연계

캠핑장 예약 서비스, 주변 장소 추천, 길안내 기능과 연결해 차박 장소 탐색부터 휴식 종료까지의 경험을 확장할 계획입니다.

### 9.4 차량 상태 기반 선제적 휴식 제안

장거리 운전 중 휴게소 도착 등 적절한 상황에서 쉼표 모드를 제안하는 방향으로 발전시킬 수 있습니다.

다만 실제 주행 상태와 운전자 주의 분산 방지 요건을 충족하는 범위에서만 제공하도록 설계합니다.

### 9.5 다양한 차량과 글로벌 시장으로 확장

차종별 공조·조명 지원 범위를 반영하고, 지역별 날씨·장소 데이터를 연결해 Pleos Connect의 확대에 대응할 계획입니다.
