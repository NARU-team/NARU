# 쉼표 제출 시나리오 점검

근거: COMMA_MVP.md, COMMA_UI_PHASE1~5_1.md와 현재 Kotlin 코드.
별도 기획서(PDF/DOCX/PPTX/기획 이름 파일)는 현재 프로젝트 검색에서 발견되지 않았다.
아래의 미확인 내용은 기획으로 추정하지 않는다. Figma 원본 추가 조회는 직전 작업에서 공통 한도에 걸렸다.
이번 제출 작업은 확인된 쉼표 디자인 시스템과 기존 화면을 재사용한다.

| 장면 | 화면·버튼 | 전환 | 데이터 | 작업 시작 시 구현 상태/차단점 |
|---|---|---|---|---|
| 진입 | 홈 쉼표 카드 | 홈→설정/최초 안내 | 모의 배터리 | 구현 |
| 최초 사용 | 안내 확인 | 예외→설정 | Android 추가 권한 없음 | 구현, 권한 허용으로 표현하면 안 됨 |
| 주차 확인 | 연동/주차 상태 확인 | UNKNOWN→사용자 확인(앱만) | 실제 신호 UNKNOWN 유지 | 구현 |
| 시간 | 15/30/45/직접, ±5, 숫자 입력 | READY 유지 | 1~180분, 종료 예정 | 구현 |
| 설정 | 공조/화면/음향/조명 카드 | READY 설정 변경 | 앱 밝기/배경/무음·톤 | 공조 미지원, DEMO 차량 적용 상태 없음(P0) |
| 자연음 | 자연음 선택/미리 듣기 | 기획 상세 미확인 | 자연음 원본 에셋 없음 | 미구현(P1), 완료로 표시하지 않음 |
| 알람 전용 | 알람만 맞추기 | 별도 시작 경로 없음 | 타이머만 필요 | 비활성(P0: DEMO 전용 별도 경로 추가) |
| 시작 | 이 설정으로 쉬기 | READY→RESTING | 앱 설정 스냅샷/복구 원본 | 일반 앱 휴식 구현 |
| 휴식 중 | 원형 타이머, 5/10분 더, 종료 | RESTING/연장/FINISHED | 단조 시계 remaining/planned | 구현 |
| 알람 | 종료 예정 시각, 5/10분 더, 종료 | WAKING→RESTING/FINISHED | 30초 확인, 짧은 톤 | 구현 |
| 자동 복구 | 확인 시간 만료 | WAKING→FINISHED | 앱 복구 상태 | 구현 |
| 완료 | 실제 시간/기록/복구, 홈/새 설정 | FINISHED→READY | Room 저장 확인/대기/재시도 | 구현 |
| 예외 | 미지원/실패/UNKNOWN/주차 아님 | RestPhase 유지 | 실제와 Mock 분리 | 구현, 실패·주행 사례를 실제 UI로 촬영할 버튼 없음(P0) |
| 주행 종료 | 실제 주행 신호 조건 | 활성→FINISHED | 실제 SDK 없음 | 가드/종료 경로만 구현, 실제 기능 미지원 |
| 빠른 촬영 | 데모 시작/종료30초 전/종료시점 | 별도 가상 시계 | Room 제외 | 설정을 건너뛰고 즉시 시작함(P0) |

원격 NARU-team/NARU README에서도 시간 선택→환경 설정→알람→상태 복구 흐름을 확인했다.
아래 P0 경로는 구현 및 단위 테스트/빌드로 확인했다. 실제 기기 촬영 체크는 README_DEMO.md를 따른다.

제출 수정 목표:
- Debug DEMO 진입→설정→15분→가상 설정 적용→RESTING→종료시점→WAKING→5분 연장→다시 알람→종료→FINISHED.
- ALARM_ONLY는 DEMO에서 별도 액션, 앱/가상 공조·조명 설정을 바꾸지 않는 타이머 경로.
- 가상 주차/온도/배터리/공조/조명/복구는 고정 초기값과 명시적 버튼으로만 변경.
- DEMO 완료는 실제 Room에 저장하지 않는다. Room 촬영은 일반 앱 휴식을 짧게 시작/수동 종료해 별도로 촬영.
- 자연음, 실제 차량 제어, 시스템 알림, 백그라운드 정시 보장, 원본 폰트/아이콘은 이번 P0 완료라고 주장하지 않는다.
